**Bug (2026-09-10, DJ's real ~62-min meeting):** `meeting.py _distill` called `client.messages.create(..., max_tokens=4000, ...)` for a RICH JSON distillation (minutes+decisions+action_items+ideas+campaigns+content+sops+roadmap+reference+open_questions). A dense hour blew past 4000 output tokens → response truncated (`stop_reason='max_tokens'`) → `re.search(r'{.*}', out, re.S)` grabbed incomplete JSON → `json.loads` threw → a broad `except Exception: return None` swallowed it → `_process_meeting` stored the generic `'distillation failed'`. (Yesterday's shorter meeting fit under 4000, so it filed — that's why it was intermittent.) `CLAUDE_MODEL='claude-sonnet-4-6'` (shared.py) supports well above 16k output.

**Fix (shipped, tips 81109449 + d838928):** `_distill` now returns **`(dict|None, err_str)`** (was dict|None). A 3-attempt loop escalates `max_tokens` 8000→16000→16000 with a short backoff, retrying on truncation (`stop_reason=='max_tokens'` / JSON parse fail) AND transient API errors; it logs `repr(e)`+`stop_reason`+`len(out)` and returns a specific error, so `_process_meeting` stores `'distillation failed: <reason>'` (not the generic string). Also added a `_DISTILL_SYS` rule to always capture concrete reference facts (named accounts/cards, rates, productivity benchmarks like "9-slider house in 1h45") into `reference[]`. **Lesson: never cap distillation output at 4000 for open-ended rich JSON, and never `except: return None` on a parse — log + surface the reason.** The wakeLock screen-sleep fix (recorder page filling with "you you you" on mic drop) is a SEPARATE queued item.

**★ HOW TO RE-KICK a stuck/errored meeting (cookie-free) — reusable recovery:** meetings live in `ir.config_parameter` **`wsc.memory.meetings`** (JSON list; `memory_store.log_meeting(mid, patch)` merges). The transcript checkpoint is a separate param **`wsc.memory.mtg_transcript.<mid>`** (survives restarts). `_process_meeting` RESUMES from that checkpoint (skips gather+transcribe) if present. The `_scheduled_meeting_retry` cron (main.py, `minute='*/10'`) calls `retry_stuck_meetings()`, which re-kicks any meeting with `status in ('processing','transcribing','distilling')` + stale `last_progress_at` (>10 min) + no `filed_at` — but NOT `status='error'`. So to re-kick an errored (or stuck) meeting WITHOUT an owner cookie: read `wsc.memory.meetings` via Odoo RPC, set the record's `status='distilling'`, `error=None`, `last_progress_at` to a stale timestamp (>10 min old), ensure no `filed_at`, write back → the in-worker cron re-kicks it within ≤10 min → resume→re-distill→file (`filed_at` set, pushes "Meeting captured ✅"). The owner-cookie path is POST `/api/meeting/finalize {meeting_id}` (spawns the thread immediately) — use the RPC status-flip when you can't mint a cookie. Verify via the record's `status='filed'` + `decisions`/`action_items` counts.
