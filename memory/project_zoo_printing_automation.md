**Goal:** auto-process Zoo Printing emails for HOF jobs. When estimate/confirmation/shipped emails arrive from `contact@zooprinting.com`, record them and advance the tracker steps. On the SHIPPED email, send the Odoo invoice to NBHOF.

**App location:** lives in `saunders-render-app` repo: `routers/printing/{jobs.py,watcher.py}` + `static/printing/index.html`. The `Saunders-Printing` GitHub repo is EMPTY (red herring). **OPERATIONAL FACTS (verified 2026-06-24 — answering "an order-shipped email came in, did the watcher do anything?"):** The Zoo watcher (`check_zoo_emails`) is **NOT** in the in-app APScheduler (main.py only schedules `check_hof_emails` every 30 min). Zoo runs ONLY via the daily Render cron above → `/printing/api/check-po` (jobs.py `manual_check_po` runs BOTH HOF + Zoo). Manual triggers: `GET /printing/api/check-zoo` (Zoo only) or `/api/check-po` (both). Consequences: (1) **Not real-time** — a shipped email is processed on the next ~11pm-PT (06:00 UTC) run, not on arrival; trigger `/printing/api/check-zoo` to process now. (2) **UNSEEN-only** — `mail.search('(UNSEEN FROM contact@zooprinting.com)')`; if you've already READ the email it's skipped → recovery is per-PO `collect_zoo_emails_for_po` (X-GM-RAW, reads even SEEN mail) via the "📧 Zoo Emails" button. (3) Zoo sends **~20 duplicate "has shipped" emails** per sub-order → watcher processes the first (`status:shipped`), rest return `ship_dup` (harmless, `shipped_at` already set). (4) On shipped it marks the sub-order + `order_shipped` step, archives the body, `_notify_dj`, and reports `invoice_ready` — it does **NOT** auto-send the invoice (deliberate PO-level one-tap: open tracker → PO → "Send Invoice"). 2026-06-24: processed PO **044167** sub-order 6734814-A, invoice_ready=true, DJ to tap Send Invoice.

**THE JOIN KEY (critical):** Zoo Order Confirmation AND Shipped emails both contain a line `Job Name: PO 043859` — the exact HOF PO number. Match Zoo order → tracker job by `po_number` via regex `Job Name:\s*PO\s*(\d+)`. The ESTIMATE email ("Your Estimate Request Is Ready To Order") has ONLY the Zoo order # in BODY ("estimate for 6725414-A is ready"), NO PO and NO Order# in subject — hold in pending bucket keyed by full sub-order id, reconcile via base→PO map.

Blob also has `zoo_order_po` (base order# → PO, lets later estimates link) and `zoo_pending_estimates` (sub-order id → estimate held until PO known).
