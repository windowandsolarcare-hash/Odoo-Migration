Stage 0 of the maintenance customer-comms lifecycle (replaces Workiz's advance heads-up). Built 2026-08-01, text-only, HUD-approval-gated now / auto-later. Files: **routers/owner/reminders.py** (kind `maint_advance`) + NEW **routers/owner/calfeed.py** (.ics) + 1 additive line in main.py.

**Flow:** lead's `create_next_maintenance_so` (dashboard.py mark-Done → next Submitted draft job) → my sweep surfaces it → DJ approves → text. `build_maint_advance()` runs inside `reminders_tick()` (scheduled */30). Selects Submitted future jobs: domain `x_studio_x_studio_workiz_status='Submitted' AND state!='cancel' AND company_id=1 AND date_order>=today-PT`, minus personal/office job types. **Do NOT filter on type_of_service_so='Maintenance'** — verified live it's set on only ~1/21 Submitted jobs, would drop nearly all. Per-job HUD **approval** card (feed.submit_item), urgency `glance`, `action`=deep link `/static/owner/v2_field.html?open_so=<id>&date_raw=<YYYY-MM-DD>`, `on_approve`=POST `/owner/api/maint/advance/send {so_id}`. Capped 12/tick.

**HUD surface = ONE aggregate card (not per-job).** `build_maint_advance()` submits a single feed card `maint_advance:review` (kind approval, badge=count, names in why_now, action→`/static/owner/v2_maint_advance.html`, on_approve→POST `/owner/api/maint/advance/send_all`) — same pattern as billing:review/reschedule:review. The review page (`v2_maint_advance.html`) lists each pending job with an Open-job verify link + per-row Send + a Send-all. Endpoints: `GET /api/maint/advance/review` (owner, returns pending + refreshes the card), `POST /api/maint/advance/send_all`, `POST /api/maint/advance/send {so_id}` (per-row, refreshes card). `_maint_pending_rows()` is BATCHED (state params + property partners + parents + opt-out list in ~5 Odoo calls total, not ~60) — per-job reads made the review endpoint take 19s; batched ≈3s. (Superseded the earlier per-job cards + MAINT_CARD_CAP.)

**Stage 1 (confirm) + Stage 2 (night-before) — added 2026-08-01, reminders.py.** `_maint_stage_rows(stage)` + shared endpoints `/api/maint/stage/{review,send,send_all}?stage=confirm|eve` + ONE shared page `v2_maint_comms.html?stage=`. Aggregate attention card per stage (`maint_confirm:review` / `maint_eve:review`), built in reminders_tick (confirm morning, eve afternoon). **Stage 1** = advance state=='ok', dated CONFIRM_LEAD_DAYS(3) out, not confirmed, not cancelled → "reply YES to confirm"; YES → `wsc.maint.confirmed.<so_id>` (public `maint_confirmed_state(so_id)`). **Stage 2** = engaged (state 'ok' OR 'sent'), NOT cancelled, dated tomorrow → message BRANCHES on confirmed (DJ's #1 rule = NO dead-ends: a silent non-responder still gets "I've got you down, I'll be there — reply if anything changed"). Inbound: the awaiting map now carries a `stage` key so a YES is interpreted per stage (advance→appt_confirm, confirm→confirmed, eve→ack); reschedule/cancel flag DJ in every stage. All approval-gated. Idempotent per stage via messaging idem `maint_{stage}:{so_id}`.

**State (ir.config_parameter, the reminders.py way):** `wsc.maint.advance.<so_id>` = JSON `{state,ts}`, state ∈ sent|ok|reschedule|cancel. **Stage 1 (3-day confirm) reads this** — public accessor `reminders.maint_advance_state(so_id)`. `wsc.maint.advance.awaiting` = `{norm_phone:{so_id,so_name,sent}}` (phone→open thread, like PENDING_KEY). Idempotency: any state present → job skipped + card withdrawn; plus messaging idem `maint_advance:<so_id>`.

**Send:** `messaging.send(kind='maint_advance', idem=...)`. Approved copy: "Hi {first}, it's Dan with Window & Solar Care. Your next service is scheduled for {Day, Month D}. Add it to your calendar: {link}. If that works, just reply OK — or ... reply back ... Thanks! – Dan". Date format = "Thursday, September 3" (no ordinal, `_day_phrase_plain`). Person = property.parent_id (via `_partner_details`).

**Inbound:** extended `reminders.handle_inbound` (so NO sms.py edit — sms.py already calls it). If not awaiting a confirm-YES → `_maint_handle_inbound`: OK (leading yes-token or key phrase) → state 'ok' + chatter + short ack + Info card; reschedule/cancel intent phrases → state + HUD card for DJ + chatter, never auto-changes the job. Carrier STOP (bare 'cancel'/'stop'/'unsubscribe') still opts out via messaging.classify_keyword FIRST (compliance) — so "cancel my appointment" = cancel request, bare "cancel" = opt-out.

**Tap-page (added 2026-08-01, DJ approved):** the Stage-0 text carries ONE link → a public branded self-service page `GET /appt/<token>` (in calfeed.py, same so-token as /cal). Shows service/day/time/address + buttons: ✓ I'll be there (confirm), 📅 I need a different day (note box), Can't make it (note box), Add to calendar (the .ics). POST `/appt/<token>/{confirm|reschedule|cancel}` → deferred-imports reminders → calls shared `appt_confirm/appt_reschedule/appt_cancel(so_id, note, source)` which back BOTH the tap-page (source='page') AND the text-reply path (source='text') — ONE code path. **Model change: silence = confirmed** (text says "you're all set, nothing to do", no "reply OK"). reschedule/cancel never auto-change the job — they set state + a HUD card ("Open the job" deep link). v1 reschedule = customer PROPOSES a day (flags DJ); true self-serve rebook (real open slots + move date_order) is a scheduler-lane fast-follow (lead owns scheduler.py). calfeed↔reminders would be circular, so calfeed uses a deferred `from . import reminders` inside handlers.

**Self-serve rebooking (2026-08-01, DJ = propose-then-approve, NOT auto-move).** On the tap-page, "I need a different day" → `GET /appt/<token>/slots` (calfeed) returns up to 3 route-tight open days via the lead's `scheduler.rank_days(prop_id, today, 21, 3, 'route')` (prop_id = SO.partner_shipping_id). Customer picks a day → POST `/appt/<token>/reschedule {choice:'pick',date,time}` → `reminders.appt_reschedule_pick` records state + drops an **approval** HUD card `maint_advance:reschedule:<so_id>` (on_approve → POST `/owner/api/maint/advance/do_reschedule`). The job does NOT move on pick. DJ approves → `do_reschedule` calls the lead's **`scheduler.schedule_odoo_so(so_id, dt_pt, set_status=True)`** (deferred import) = confirm draft + write date_order (PT→UTC) + status Scheduled. "None of these work" → free-text → the plain `appt_reschedule` path (flags DJ, no move). LESSON: chain `node --check … && push` — a bad quote-escape once got pushed because the check and push weren't `&&`-chained.

**calfeed.py (.ics):** public `GET /cal/{token}.ics` (registered in main.py WITHOUT prefix). Token = `<so_id>-<10hex HMAC over "so:"+so_id>` using `BOOKING_TOKEN_SECRET` (booking.py's salt; it signs a DIFFERENT message — booking signs bare partner_id, so tokens aren't cross-usable). `cal_link(so_id)` builds `https://wscare.pro/cal/<token>.ics` (PUBLIC_BASE_URL env, default wscare.pro — verified wscare.pro routes to the app). VEVENT: DTSTART=date_order UTC Z, DTEND +90min (no job-length field), SUMMARY, LOCATION=property street+city, ORGANIZER. Verified 200 text/calendar on both hosts. See [[project_workiz_retirement]].
