**Key gotchas:**
- `customer_jobs` does NOT return `workiz_uuid`; its `workiz_link` is `https://app.workiz.com/job/{uuid}/`. Derive uuid client-side: `String(j.workiz_link||'').match(/\/job\/([^\/]+)\//)`. (Note: this URL form is `/job/{uuid}/`, NOT the `/root/job/{uuid}/1` form used elsewhere.)
- Customer name for the menu's `data-customer` (delete/note dialogs) is read off the card: `card.querySelector('.cust-name').textContent`.
- The menu's actions (`syncJobFromMenu`, `deleteJobFromMenu`, `markBlockDone`) call `loadField()` which refreshes the **schedule**, not the brain box — so after a menu Delete the brain row stays until you collapse/re-expand. The Sync **pill** (syncCustJob) repaints in place; the menu's Sync does not. Acceptable gap, not yet wired to repaint the brain.

**Return-to-brain on close — FIXED 2026-06-25 (commit 2b70fb3):** opening a job from a brain job row (`openCustJob`) tears down the office-panel overlay then calls `openJob`, so closing the job (`apBack` → the `‹ Back` button, field.html L973) landed DJ on the SCHEDULE, not back on the customer's job list. Fix = a `window._returnToCust` flag: `openJob` clears it to null on every open (default close→schedule); `openCustJob` re-sets `{pid,name}` AFTER each `openJob` call (both the live and non-live branches); `apBack` checks it FIRST — if set, `closeActive()` + `openCustomersTab()` + `preloadCustomer(name,pid,true)` (which auto-expands via `_custAutoOpenPid`) to land back on that customer with jobs open. Order matters vs the existing `_backToCC` (history.back) branch — `_returnToCust` is checked before it.
