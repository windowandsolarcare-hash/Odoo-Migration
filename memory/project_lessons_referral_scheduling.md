**Context (DJ 2026-09-05):** the Jim→Robert referral and the Linnea reschedule each took "too many bites at the apple" (many turns = DJ's time). Lessons to not repeat:

1. **Front-load the customer's CONSTRAINTS before scheduling.** Read their latest thread/voicemails for day/time preferences + service details FIRST, and ask ONE clarifying question, before booking. Don't book then re-book. (Linnea flip-flopped Tue→"week later, not Tuesday, my cleaning lady comes Tuesday" — booking before confirming her window caused the redo.)

2. **For an add-on the customer "had before," search line-item DESCRIPTIONS, not just product names.** Linnea's 3 front lights were logged on a past job under **"Mirrors Cleaned" ($25)** with the real detail in the line description — a product-name search missed it. Dump past SOs' full line rows (name + description) when hunting a prior charge.

3. **Verify weekdays ONCE up front with a date calc** — don't eyeball. (Misstated Robert's Thu/Fri as Sep 11/12 when it was Sep 10/11.)

4. **When DJ says "yes to all" / "do it for this referral," run the WHOLE play in one pass** — lookup → create contact/property → create job → reserve slots → draft the card — not piecemeal across turns.

5. **Calibrate pitch/offer with DJ UP FRONT, not after.** Ask "how hard to push / how many slots / which days" before drafting. (Over-pushed Wednesday then had to soften; offered 3 slots then dropped one — both avoidable with one question first.)

**Net rule:** gather constraints + one clarifying question → then execute the full operation in a single pass. This is also why we're building "plays" (named shortcuts) and voice tools — to make the whole operation one step.
