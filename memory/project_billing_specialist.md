**Process model (DJ-corrected):** jobs are only marked Done AFTER billing, so stuck jobs are NEVER "Done + unpaid" — they are **past their scheduled date and still NOT Done** (worked, but the billing step never started). While un-Done, Phase 5/6 never fire → next maintenance cycle silently never schedules. This unblocks both.

**Detection** `detect_candidates(today, lookback=60)` — extends the canonical stale-SO query (does NOT write a 3rd copy): `company_id=1`, `state in [sale,done]`, `date_order in [today-60d, today)`, `x_studio_x_studio_workiz_status NOT IN [Done, Canceled, Submitted]`. Excludes: name/type containing personal/time-off/vacation; pure $0 blocks with no workiz_uuid; snoozed customers (`x_snooze_until` future, parent-preferring). Per-row: worked-evidence = effective_hours>0 on linked project.task OR amount>0 → classification worked|ambiguous; route = stripe if last payment method (via `_last_payment_method_by_partner`) contains "credit" else zelle; needs_price = amount<=0.
