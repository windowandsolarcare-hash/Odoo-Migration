**Strategic direction (DJ, 2026-06-21):** the owner app feels like "a bunch of add-ons, not a designed app." The fix is a cohesive **ERP**, NOT more one-off screens.

**FRAMING CORRECTION (DJ, 2026-06-21) — DO NOT DRIFT FROM THIS:** "I'm creating an **ERP-like system, not a reporting system.** Customer is the brain, but the **SCHEDULE is the HEART** — everything else complements the schedule and the business." So: HEART=the field schedule/calendar/dispatch (where jobs land, get worked, get paid — the day in the field IS the business). BRAIN=the customer record (know everything, decide & solve). Everything else = complements that FILL the schedule (reactivation, maint-due, booking, new orders, quotes), RUN it (field assistant, route/GPS, timer, payments), or feed MONEY/TEAM/LEARN/GROW. **Reports are FEEDER LANES, not the centerpiece** — every report answers "what goes on the schedule next?" or "what's falling through that I must fix?", and rows resolve INTO the schedule (book) or INTO the brain (solve). The unified result component + Brain action sheet = the MECHANISM/plumbing, not the product. Don't pitch this as "a reporting system."

**Authoritative spec** (read/update this, not this memory file for detail):
`docs/REPORT_HUB_ARCHITECTURE.md` in `saunders-render-app` (mirror in `Odoo-Migration/3_Documentation/`).

**The vision in one line:** Reports are *lenses* (a registered query returning standard rows) → all render in ONE shared **Result component** (same format, different data) → tapping any row opens ONE universal **Brain** detail+action sheet where you SOLVE it in place (sync/reschedule/mark-paid/SMS/edit/book/delete). Selector = **cards → pills** (hub shows report cards w/ live counts; opening one shows a pill row to hop between related reports).

**Key contracts (see spec §4):** `ReportRow` standard shape (entity/entity_id/title/badges/actions/links); `ReportDef` registry (`rows(filters)=>ReportRow[]`); backend `GET /owner/api/reports[/{key}]`; `openBrain(entity,id)`.

**Survey findings that justify it (2026-06-21, 4 Explore agents over the cloned repo):** ~58 report surfaces / 30 files; NO shared UI (5 palettes, 6 pill styles, 5-7 result looks, 4 headers); most reports DEAD-END (worst: Stale SOs, Brain SO-detail, Pre-Deposit) — proof in-place works = Maintenance set_slot + Reactivation book; `dashboard.py` = 12,393-line god-file / 243 fns / ~15 domains with dozens of SHADOW routes that override the real routers (root cause of the recurring "edited the wrong file" bug — see [[project_scheduled_sos_shadowed_in_dashboard]], [[project_reactivation_route_shadowed_in_dashboard]]).

**Phasing (spec §6):** P0 common.css + report_kit.js (no behavior change) → P1 Hub + 3 flagship reports (Overdue Maint / Stale SOs / Reactivation Due) → P2 the Brain (big build: inline edit/reschedule/pay/SMS) → P3 migrate rest. Parallel DEBT track: delete shadow routes + split god-file.
