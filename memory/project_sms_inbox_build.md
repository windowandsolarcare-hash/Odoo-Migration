Building a best-in-class in-app customer texting inbox for when the numbers port off Workiz to DJ's own Twilio ([[project_twilio_port_from_workiz]], cutover Fri 2026-06-26). Replaces Workiz's messaging. **Goal: much better-organized than Workiz's read/unread** (which buries messages).

**Core design (DJ-approved 2026-06-23):** conversations are a TRIAGE QUEUE, not read/unread. States = 🔴 **Needs Reply** (auto: customer texted last) / 😴 **Snoozed** (resurfaces at a time) / ✅ **Done**. A convo leaves the main view only when DJ snoozes/closes it — reading never buries it. Model borrowed from Front/Intercom/Help Scout/Missive. On top: tags, ⭐priority, filters (Needs-Reply/Snoozed/Done/by-tag/Unknown), full-text search incl. imported Workiz history, customer-context panel (Odoo: next job/last service/balance), AI-draft + quick replies, snooze→My Day.
**DJ choices:** team = **just DJ** (no assignment); tags = **New Lead/Quote, Scheduling/Reschedule, Payment/Invoice** (+ default General); **My Day = unified** (Needs-Reply convos mirror to a project.task so they show in My Day); **push only, NO email** (too many already); experience = Workiz-style everything-in-app, NOT customer texts landing in DJ's personal Messages.

**Alerting:** web push ONLY (VAPID already set up, [[reference_vapid_webpush_keys]]) — independent of Twilio so it works on cutover regardless of A2P. Push = doorbell → tap → opens conversation IN the app. NOT SMS-to-DJ's-phone (that clutters his Messages + depends on Twilio outbound).

**Architecture (no custom Odoo models — SaaS forbids):** (1) thread texts → log to res.partner chatter = unified comms log w/ [[project_workiz_chat_export_to_odoo]]; (2) per-conversation triage state → ir.config_parameter JSON keyed by normalized phone (same pattern as Reference cards / existing sms.pending); (3) Needs-Reply convo → create/sync project.task for My Day. Twilio send = httpx, no twilio pkg.

**Existing code:** `routers/owner/sms.py` (saunders-render-app, 216 lines, ALREADY mounted in main.py at `/owner` → webhook live at `/owner/api/sms/incoming`). It does inbound→customer-lookup→AI draft→**texts DJ's phone**→reply-Y-to-send, queue in ir.config_parameter. **3 BUGS/GAPS to fix:** (1) 🔴 BLOCKER `_find_customer` queries `mobile` field which does NOT exist on res.partner in Odoo 19 → throws on every inbound → silently swallowed → currently 100% broken; (2) outbound (reply AND the SMS-alert) may be carrier-blocked until A2P 10DLC re-registered post-port — switch alert to push; (3) no Odoo history logging (message_post) — texts not saved to customer.
