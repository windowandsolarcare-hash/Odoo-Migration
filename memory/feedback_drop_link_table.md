DJ 2026-09-09: **"drop link table."**

**What to STOP:** the habit (started by Cheryl's cloud, followed fleet-wide) of ending replies with a big multi-row TABLE/LIST of app links (a ten-row menu of every surface). Do NOT append a link table to replies anymore.

**Why:** Cheryl (the real user) said unprompted "there's multiple interfaces… I can't tell which is the app." A ten-row link list in chat + a home screen + a FAB launcher = three competing "front doors." The link table was making the multiple-interfaces problem worse, not better. DJ ruled to drop it.

**How to apply:**
- No end-of-reply link-table/menu. Full stop.
- **BUT keep the single-link habit:** when you reference ONE specific thing DJ/Cheryl must open (a preview, an artifact, a report, a picker), still paste that ONE clickable markdown `[text](url)` link — [[feedback_always_paste_preview_link]] still stands. The rule kills the *table of many links*, not the *one relevant link*.
- The `🟢/🟡 <Role> — OVER` status line still ends every reply — [[feedback_over_status_line]] is unchanged.
- Nuance vs [[feedback_repeat_portal_link_every_save]] (Portal repeating the picker link every save): that was ONE link, which is fine under this rule — but re-confirm with DJ if it starts feeling like clutter too.
