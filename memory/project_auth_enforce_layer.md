**The auth layer (discovered 2026-08-22 during the P0 security task).**
- **Middleware:** `main.py` `_authz_gate` (@app.middleware http) calls `authz.check(request)` on every request. Protected prefixes = `/owner`, `/tech`, `/cheryl`.
- **`authz.check()` passes if:** path in `PUBLIC_PREFIXES` (`/api/login`,`/api/logout`,`/healthz`,`/static`,`/book`,`/c/`,`/sw.js`, plus machine/automation `/owner/api/owntracks/webhook`,`/owner/api/cron/`,`/owner/api/payroll/cron`,`/owner/api/tasker/`,`/owner/api/sms/incoming`, and customer-facing `/owner/api/booking/intake`,`/owner/api/stripe/tip_page|logo|check_payment`,`/owner/api/zelle/pay|track`) OR path in `PUBLIC_EXACT` (Twilio voice TwiML callbacks + `/owner/api/job/gallery`,`/owner/api/job/photo`) OR it carries a valid `wsc_session` cookie whose role allows the path (**owner opens everything**; tech→/tech; cheryl→/cheryl).
- **`AUTH_ENFORCE` env** (`authz.enforcing()` = `os.environ['AUTH_ENFORCE']=='1'`): when set, a failed check → 401 (or redirect to `/` for HTML). **When UNSET (current state) = MONITOR MODE:** the request is ALLOWED anyway, and the would-block is recorded. ★ So right now the ENTIRE /owner surface answers anonymous requests — that's the P0 (Portal found `/owner/api/portal/link` + `/owner/api/intake/search` leaking customer PII + working portal links to plain curl).
- **Session cookie `wsc_session`** = HMAC (`v1.<b64 {n,r,exp}>.<sig>`, secret = `SESSION_SECRET` env falling back to `ODOO_API_KEY`), `secure;httponly;samesite=lax;path=/`, 180-day sliding (renewed by middleware past half-life). Minted ONLY by `POST /api/login` (routers/auth.py): name + `x_render_pin` → role from `x_render_role` on res.partner. Login page = `static/login.html`.
- **Make-safe tool = the would-block report** `GET /owner/api/authz/report` (reachable anon while monitor-mode): every path that WOULD 401 under enforcement, with a **reason** (`no-cookie` / `bad-or-expired` / `role-mismatch`), persisted to `ir.config_parameter 'wsc.authz.monitor'` (flushed every 15 min by briefing_tick → survives deploys). ★ Read it by **recent `last` timestamp**, NOT raw count — top counts (owntracks 9126, sms/incoming, voice/*) are STALE persisted rows for paths since whitelisted; `curl/8.18.0` rows are our own tests.

**Why we did NOT flip (2026-08-22):** the report shows **DJ's Android field-app UA would-blocked on core endpoints** — `no-cookie` on `/owner/api/dashboard`,`/whoami`,`/myday`,`/payroll/status`,`/inbox/*` and `role-mismatch` on `/appver`,`/feed/badge`,`/library/*`. `no-cookie` = the installed PWA/webview isn't reliably sending `wsc_session` (split cookie jar). **Flipping now = DJ locked out of his field app.** Make-safe MUST come first.
- ~~**Lower-risk option proposed to Lead:** extend `authz.check()` to also accept a valid **`access_code` (AC)** as an alternative to the cookie.~~ **★ KILLED 2026-08-22 — DO NOT BUILD THIS.** Specialists checked AC's entropy first (Lead's condition 1) and found the field app's `access_code` is the **hardcoded literal string `'owner'`** (`v2_field.html` `var AC='owner'`; server `whoami` special-cases `code.lower()=='owner'`). It ships in client JS, so it is **public knowledge with ZERO entropy** — accepting AC at the gate would accept `?access_code=owner` from anyone and leave the leak 100% open. No rate-limit fixes a published constant. **Corollary discovered the same way: the V2 app NEVER calls `/api/login` and holds NO `wsc_session` cookie at all** — that's why the report shows `no-cookie` everywhere (it never had one, it's not a flaky cookie jar). So the only real fix is giving the V2 app a genuine session, then enforcing the cookie; there is no AC shortcut and no zero-risk interim.
- **Sequence:** make-safe (AC-in-gate and/or fix PWA cookie + Operator logs in via `/api/login`+PIN) → soak with enforcement OFF → fresh report shows zero real would-blocks → flip `AUTH_ENFORCE=1` (Render env **POST/merge, NEVER PUT** [[feedback_render_put_env_vars]]) **with DJ's device present + instant rollback (unset env)** → verify by CONTENT (anon curl → 401 zero data; DJ + Operator still work).
- **Token caveat (Portal's `make_token`):** stateless HMAC, no expiry/revocation — issued portal/booking links stay valid forever even after enforcement; durable fix = add expiry/revocation (Portal ticket); rotating `TOKEN_SECRET` nukes ALL live links at once (DJ's risk call).
