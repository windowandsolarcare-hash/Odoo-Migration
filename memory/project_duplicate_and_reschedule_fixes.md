**★★ DEBUGGING LESSON (cost ~15 deploys) — two traps stacked:**
1. **`rank_days` is a thin wrapper over `_rank_days_at`** (the coord-based CORE that holds the actual ranking + `if ordering==...` block + option list). Adding a param to the wrapper alone → `NameError: name 'ordering' is not defined` from the CORE. When editing scheduler ranking, edit `_rank_days_at` AND thread the param through `rank_days`'s call to it. `city-suggest` also calls `_rank_days_at` directly.
2. **Render deploy propagation takes ~3-4 cycles (~90-120s AFTER the deploy shows "live")** — old instances drain and keep serving the previous code, so a just-pushed change looks broken/unchanged for a couple minutes. This masqueraded as "the deploy won't update / static updates but Python doesn't." ★ Before concluding a deploy is stuck: (a) verify GitHub HEAD is correct, (b) poll the live endpoint for **5+ minutes** with a cache-buster (`&_cb=$RANDOM`), (c) watch for the error TEXT changing (proof new code is landing mid-propagation). A genuine NameError from provably-correct source = a wrong-scope/duplicate-function bug, NOT a deploy problem.
