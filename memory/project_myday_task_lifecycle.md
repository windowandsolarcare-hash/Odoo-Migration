**Built 2026-07-06 to fix DJ's core My Day pain: a flat inbox sorts by arrival, so "waiting" tasks (doing→waiting→doing work) sink and get lost, and important things get buried.** DJ approved: 4 statuses (To Do/Doing/Waiting/Done), Waiting resurfaces on an exact date + 3 quick buttons, and checklists inside a task.

**Odoo fields on project.task (created 2026-07-06):** `x_myday_status` (char id 21356: todo|doing|waiting; Done = existing state 1_done, NOT a stored status), `x_myday_wait_until` (date id 21358, the resurface/check-back date), `x_myday_checklist` (text id 21360, JSON `[{"t":"step","d":bool}]`).

**Backend (`routers/owner/myday.py`):** get_items reads the 3 fields + computes per item: `status`, `wait_until`, `resurfaced` (=status waiting AND wait_until<=today), `waiting` (=waiting AND not resurfaced = parked), `checklist`, `chk_total`, `chk_done`. add/update endpoints accept status (todo/doing/waiting only)/wait_until/checklist. `_tdy=today.isoformat()` for the compare.

**Frontend (`static/owner/myday.html`) — grouping (the actual fix):** render() pulls tasks OUT of the normal date groups: **🔔 "Back — was waiting"** (resurfaced) renders at the TOP right after Pinned so a waiting task that came due is never lost; **⏳ "Waiting"** (parked, future/no date) is a collapsed group at the BOTTOM, out of the active list; plus the existing 📅 On the schedule group. So the list is organized by ACTIONABILITY, not arrival. Card chips: 🔔 was due / ⏳ Waiting · <date> / 🟡 Doing / ✓ done/total. Editor: Status button row (reuses `.quick`/`.sel`; "✅ Done" calls existing `tkDone()`, the 3 others call `tkSetStatus`), a Wait row (date + +3d/+1wk/+2wk `tkWaitPlus`) shown only for Waiting, and a Checklist editor (`tkChk[]`, tkChkAdd/Del/RenderChk, add-step input). Commits: myday.py 90553c00, myday.html fb7625e5.

**REFINED 2026-07-06 (DJ):** (1) **Doing has its own home** — a 🟡 Doing group near the TOP (under Pinned/Resurfaced, above the normal To Do groups); Doing items are pulled out of the normal pool. (2) **Resurface (check-back date + pin-on-resurface) now applies to Doing too, not just Waiting** — backend `_resurf = status in ('doing','waiting') and wait_until<=today`; editor shows the wait row for doing OR waiting; save sends wait_until for both. A Doing task stays visible in the Doing group until its date, then jumps to 🔔 (and pins if checked). (3) **Removed the "✅ Done" status button** — Done is NOT a status; complete a task via the editor footer "✓ Done" button (id tkDone) or the card checkoff (both already existed). Statuses are now just To Do / Doing / Waiting. Resurfaced group label is status-neutral ("🔔 Back — time to look"). Verified E2E: doing+past-date → resurfaced+pinned; doing+no-date → Doing group.

**ONE FORM — "+ New" now opens the SAME editor as existing tasks (2026-07-06, commit 9f34f08a).** DJ: "not certain why we don't just use editor for new." The editor is a strict SUPERSET of the old Add sheet (adds Status/resurface/checklist/action-zone), so `openSheet()` was retargeted to open the task-modal in NEW-MODE: `_tkNew=true`, `_tk={id:0}`, all fields blanked to defaults, title "New reminder", **#tkActionZone + #tkDone hidden** (can't attach automations / complete a task that doesn't exist yet). Attachments STAGE in `_addFiles` (reusing the old Add-sheet array) via `tkFilesPicked`'s `_tkNew` branch + `tkRenderStaged()`; `tkSaveEdit` branches: new → POST /api/myday/add then `uploadFilesTo(id,_addFiles)`, else → update. `closeTask` resets `_tkNew`/`_addFiles`; `openTask` sets `_tkNew=false` + restores the hidden elements. The old #add-modal HTML + saveReminder/renderAddAtt/buildQuick are now DEAD but left in place (harmless). Prevents the exact drift that left status/checklist off the old Add sheet. Verified E2E: add with full body → status/priority/resurface/pin/checklist all persist.

**PIN-ON-RESURFACE (added 2026-07-06):** field `x_myday_pin_on_resurface` (bool, id 21362) — a checkbox in the editor's Waiting section ("📌 Pin to the very top when it comes back"). Backend computes `pinned = manual_pin OR (resurfaced AND pin_on_resurface)` (display-only, no write) so on its wake day the task lands in the 📌 Pinned group (above the 🔔 resurfaced group). Verified: waiting+past-date+pin_on_resurface → resurfaced=True, pinned=True.

**ATTACHMENTS (My Day tasks, fixed 2026-07-06):** backend attach/retrieve/delete all work (`/api/myday/attach|attachments|attach_delete`, res_model=project.task, up to 10MB+ tested). Two fixes: (1) upload used to swallow ALL errors silently → now `_attachOne` surfaces failures (server/timeout/network) + 30s AbortController timeout — DJ's "attach did nothing" was a swallowed error on stale cached code. (2) `attachment_image?dl=1` (dashboard.py) adds `Content-Disposition: attachment; filename=` → downloads the real file so the phone's Open-with/Share offers HP Smart to PRINT (inline view had a stripped share sheet). ⬇ download button added to My Day tiles (myday.html renderTkAtt) AND the field.html documents viewer (openCustomerDocs). ★ The app's page-load is service-worker network-first w/ 3.5s timeout (sw.js) → a cold-start >3.5s serves a STALE cached page; fully close/reopen to force new code.

**Verified E2E via live endpoints:** future wait → waiting=True/resurfaced=False/chk 1/2; POST /api/myday/update wait_until=past → resurfaced=True/waiting=False. See [[project_myday_reminders]] for the base screen; pinned lane in same render.

**GOTCHA:** raw XML-RPC `project.task.write`/`unlink` from a local script can trip a BaseAutomation hook (`make_write() missing 'vals'` / `unlink() takes 1 positional arg but 2 given`) — but the app's own `odoo_rpc` write path works fine (that's what the update endpoint uses). For local cleanup, plain `unlink([[id]])` (no context kwarg) works on fresh tasks.
