**2026-06-15 incident:** Pushed `new_job.py` (and briefly order.py/new_order.html) as EMPTY files via raw `gh api PUT`, which crashed the Render app boot (`AttributeError: module 'routers.owner.new_job' has no attribute 'router'`). Site stayed up only because Render serves the last-good build on `update_failed`. Three compounding root causes:

1. **Pushed a file I hadn't fetched/created locally this session.** An earlier temp cleanup (`rm -f /c/Users/dj/*.py`) had deleted my local new_job.py; the push then read a missing file → empty content. **Rule: never include a file in a push batch unless you fetched or wrote it THIS session and it's on disk.**
2. **No empty guard.** `powershell Get-Content` on a missing file returns empty → b64 empty → pushed empty. **Rule: before any `gh api ... PUT`, check `[ "${#b64}" -lt 1000 ] && abort` (or an appropriate floor). safe_deploy.py has a regression guard — prefer it for large/critical files; raw pushes have NO guard unless you add one.**
3. **Colon in Windows path broke bash field-splitting.** Looping over `"path:C:/Users/dj/file:msg"` and splitting on `:` made the local path just `"C"` (the `C:` drive colon). **Rule: pass push args as separate quoted positionals, never colon-delimited when a value contains `C:/`.**

**Also (same session):** native Windows Python does NOT understand Git-Bash `/c/Users/...` ABSOLUTE paths — `open('/c/Users/dj/x.js','w')` fails / writes to the wrong place. Use RELATIVE paths (after `cd /c/Users/dj`) or real `C:\` paths in Python invoked from the Bash tool. Reading relative filenames works because bash `cd` sets the process cwd.

**2026-06-24 RECURRENCE — new footgun: in-place `wb`-then-`rb` read TRUNCATES the file.** Tried to normalize CRLF in place with `open('f.py','wb').write(open('f.py','rb').read().replace(...))`. Python evaluates the **`open(...,'wb')` first** (which truncates the file to 0 bytes on open), THEN evaluates the argument `open(...,'rb').read()` — now reading the already-empty file → wrote empty → b64 len 0 → pushed EMPTY phase5 over live (commit d5179af). The `b64 len: 0` printed but the script pushed anyway (no guard in that copy). **Rules reinforced:** (a) NEVER read and write the same file in one expression — read fully into a var with one statement, then write with a separate statement; (b) the `[ "${#b64}" -lt 1000 ] && exit 1` guard is MANDATORY in every raw-push block, not optional — the restore push had it and worked. Recovered same as below.

**2026-07-11 RECURRENCE (again!) — MSYS path in a multi-file push LOOP.** Pushed booking_requests.py + .html as EMPTY (crash: `module 'routers.owner.booking_requests' has no attribute 'router'`, deploys `update_failed`). Cause: a `for pair in "path:localname"` loop built `lf="/c/Users/dj/br_live.py"` (Git-Bash MSYS path) and passed it to `powershell [System.IO.File]::ReadAllBytes('$lf')` — **PowerShell can't resolve `/c/Users/...`, threw, `2>/dev/null` swallowed it → b64 empty → pushed empty.** AND the loop's push helper had NO b64-length guard. **Reinforced rules:** (a) in PowerShell ReadAllBytes ALWAYS use a real Windows path `C:\Users\dj\file` (single-quoted), NEVER the MSYS `/c/...` form — earlier working pushes used `C:/Users/dj/...`; (b) the `[ "${#b64}" -lt 1000 ] && abort` guard is MANDATORY in EVERY push path INCLUDING loop helpers — I keep dropping it when refactoring into a function. Recovered by fetching last-good (?ref=<sha>) + re-pushing with `C:\` paths + guard.

**2026-08-17 RECURRENCE (AGENT_MAIL.md wiped) — `python3 -c "open('/dev/stdin')"` fails on this Win/Git-Bash → empty output → empty PUSH.** Tried to mark a mail entry ✅ by piping the 405KB AGENT_MAIL.md through `python3 -c "s=open('/dev/stdin').read()..."` — **`/dev/stdin` does not exist here → FileNotFoundError → the output file `mail_new.md` was never written → `powershell ReadAllBytes` on the missing file returned empty (2>/dev/null swallowed it) → pushed an EMPTY 0-byte AGENT_MAIL.md, wiping the whole shared mail brain.** The mark-handled push had NO `${#C}` guard. **Reinforced:** (a) to edit a large existing file, use the Read+Edit TOOLS (fetch to a `C:\`/`C:/` path, Read, Edit, push) — NOT a `python3 -c` stdin pipe; (b) NEVER `open('/dev/stdin')` from Bash-invoked Python here; read a real file arg instead; (c) the `[ "${#C}" -lt <floor> ] && exit 1` guard is MANDATORY on EVERY push (I dropped it again). Recovered instantly: `gh api contents/AGENT_MAIL.md?ref=<parent_sha>` (the pre-wipe commit) → verified 2238 lines/405KB → re-pushed with guard. No mail lost.

**Recovery:** fetch last-good content from git history (`gh api contents/<path>?ref=<good_sha>`), verify it has the expected symbols (`router = APIRouter()`), re-push with verified b64 length. ALWAYS check `list_deploys` for `update_failed` after a push ([[project_render_deploy_failed_check]]).
