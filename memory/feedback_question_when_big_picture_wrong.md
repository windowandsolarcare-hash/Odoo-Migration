**DJ, 2026-07-22 (standing rule).** The most important thing DJ wants: when the BIG PICTURE of a task looks wrong, **QUESTION it before acting** — a quick question avoids the headache.

**Why:** DJ asked one session to update all V1 pages to the agreed V2 launcher format. That single session hardcoded the same floating launcher into **34 separate pages** instead of extracting one shared file — "caught in the rhythm of executing the task instead of seeing the big picture." It had every V2 page open in the same session (it even did a cross-cutting alphabetize across all of them), so it had certainty — not a hint — that the launcher lived on many pages. It still duplicated, because it optimized "complete the stated edit" over "flag the obviously wrong structure." See [[project_v2_launcher_duplicated_stale]].

**The trigger:** the 2nd–3rd near-identical edit across files. Repetition is the loudest smell that something should be centralized. That moment is a HARD STOP to ask, not a to-do list to grind through.

**How to apply:**
- On any "do X to every page / all the Y / roll this out everywhere" task: before batch-editing, ask *"this is duplicated across N files — want one shared source they all call, instead of N copies?"*
- Batch/mechanical work makes models go on autopilot and stop re-evaluating the design per file. Deliberately break that: pause when you feel a rhythm forming.
- **Neither extreme is right.** Don't mechanically duplicate (creates the mess). Don't unilaterally refactor working code either (violates [[feedback_never_remove_working_code.md]] / surgical-edits). The move is to ASK which DJ wants.
- Executing correctly at the line level while the overall structure is wrong is STILL a failure. Judgment > throughput.
- DJ's real pain: models damaging/bloating working code when a 10-second question would have avoided it. Default to the question. Related: [[feedback_confirmation_policy]] (routine tasks: just do them; but a wrong-shaped structural task is NOT routine — surface it), [[feedback_reuse_canonical_endpoint]] (one canonical place, not duplicated entry points).
