Built 2026-06-16. Lets DJ drop a non-job item onto the field schedule as a timed **Personal Time** block (his example: "Steve today").

**Backend:** `POST /owner/api/schedule/add_block` in `routers/owner/dashboard.py` (added right after `api_upcoming`). Body `{name, date (YYYY-MM-DD PT), time (HH:MM 24h PT), notes?}`. It:
- PT→UTC via module-level `_PT = ZoneInfo('America/Los_Angeles')`: `datetime.strptime(...).replace(tzinfo=_PT).astimezone(utc)`.
- Find/create the **"Personal Time" res.partner (id 23054** today; resolved by name to be safe — it's a `Contact`, `company_id=False`).
- Create `sale.order` {partner_id=PT, company_id=1, date_order, x_studio_x_studio_x_studio_job_type='Personal Time', x_studio_x_studio_notes_snapshot1='[Job Notes] {name}\n{notes}'}.
- `action_confirm` then **write date_order back** (Odoo 19 resets it to now() on confirm — CLAUDE.md rule 8).

**Why these specifics (verified by direct RPC 2026-06-16):**
- Schedule TODAY builder (`tool_get_schedule`) filters `state in ['sale','done']` → a new draft SO is invisible until confirmed. Confirming an **empty SO (no order lines) WORKS** in this Odoo 19 instance (no "needs lines" block).
- Schedule row shows `customer='Personal Time'` + description = `_personal_time_desc(notes_snapshot1)` (strips the `[Job Notes]` prefix). See [[project_personal_time_schedule_desc]].
- No SOs currently use partner 23054 — existing Personal Time rows are synced from Workiz. Blocks created here use 23054 directly.

Opens `#block-modal` (te-sheet pattern): name, date (default today), **15-min time dropdown built inline `_fillBlockTimes` 6AM–8PM** (field.html does NOT load route_map.js/WSCTime), notes. `submitBlock()` POSTs add_block, double-tap+15s-timeout guarded, then `loadField()`.

**Deleting a block (added 2026-06-18):** the field schedule's 3-dot menu "🗑 Delete Job" item used to be GRAYED OUT for a Personal Time block (the disabled state when a row has no Workiz uuid). Now: when a row has **no uuid but has a soid**, the item is ENABLED and labeled **"Delete Block"** (or "Delete (Odoo only)" for a non-PT Odoo-only SO) and routes to an **SO-only delete** = `POST /owner/api/cancel_so/{so_id}` (which just calls `action_cancel`; state→cancel drops it off the schedule gate `state in sale/done`). NO Workiz call (there's no Workiz job). `deleteJobFromMenu(btn)` in field.html now branches on `!uuid`: requires soid, confirms, calls cancel_so, closes the open detail if it's that SO, `loadField()`. This mirrors calendar.html's `cancelJob` fallback for no-Workiz rows (same `cancel_so`). The full delete (`/api/delete_job` by uuid, Workiz+Odoo) is unchanged for real jobs. NOTE: cancel leaves a canceled empty SO behind (harmless — filtered out everywhere); did NOT unlink to avoid touching the shared `cancel_so` endpoint. See [[project_delete_job_paired]].

**Marking a block DONE (added 2026-06-18):** DJ wanted to keep some completed blocks on the schedule (vs deleting). The 3-dot menu now also shows **✅ Mark Done** (and **↩ Mark Not Done** when already done) for any no-Workiz SO (`!uuid && soid` — Personal Time block or Odoo-only job), right above Delete. Menu button carries `data-status` now. So per-block: Mark Done (keep as record) OR Delete Block (remove) — DJ's choice.

**Moving/rescheduling a block (added 2026-06-24, DJ: "I put Brenda today, never went, want to move to tomorrow without delete+re-enter"):** the 3-dot menu now shows **📅 Move / Reschedule** for Personal Time blocks only (`!uuid && soid && customer === 'Personal Time'`), above Delete. It reuses the SAME add-to-schedule sheet in EDIT mode. Two new dashboard.py endpoints (after `add_block`):
- `GET /owner/api/schedule/block_info?so_id=` → `{ok, name, notes, date (PT YYYY-MM-DD), time (PT HH:MM 24h), job_type}` — reads date_order (UTC→PT) + `_personal_time_desc(notes_snapshot1)` split on first `\n` into name/notes. Used to prefill the editor.
- `POST /owner/api/schedule/move_block` `{so_id, date, time, name?, notes?}` → rewrites **date_order only** (PT→UTC) + optionally `notes_snapshot1` if a name is supplied. **No action_confirm** (SO already confirmed; re-confirming would reset date_order). GUARDED: refuses any SO with a workiz_uuid or job_type != 'Personal Time' → "Only Personal Time blocks can be moved here" (so a real job's date can never be moved here = no Workiz desync). Verified end-to-end 2026-06-24 (create→read→move→guard-reject-real-job→cleanup).
