## COLD-START RESILIENCE FIX 2026-06-16 (booking index.html)
DJ hit a **502 on first load** then it worked on retry, but the **service question (step 1) showed no options**. Cause: service is on Render **Starter, numInstances=1** (always-on — NOT a spin-down; the free tier spins down, Starter doesn't). The 502 was a transient single-instance restart (no redundancy → momentary 502). On the recovered page, `loadServices()` had `try/catch` that swallowed the failed `/book/api/job-types` fetch and rendered an EMPTY list with NO retry → step 1 blank. FIX: added `jfetch(url,tries=4)` retrying with backoff (rides through 502/spin-up) used by loadServices + loadCities, AND a hardcoded `SVC_FALLBACK` (the 4 JOB_TYPES) so step 1 is NEVER blank even if the API is down. Lesson: customer-facing fetches must retry + have a static fallback for required inputs; a bare try/catch that renders empty is a silent dead-end. To kill 502s entirely would need numInstances≥2 (more $) — not worth it unless recurring.
