**Serving trick (no collision risk):** `main.py` mounts `app.mount("/static", StaticFiles(directory="static"))`. So any new file dropped in `static/owner/` is reachable at `/static/owner/<name>.html` with **NO route change and NO edit to any shared file** (main.py, routers). Preview pages use absolute `/owner/api/...` fetches, so they read the real live data regardless of their own URL. This is the safe way to ship redesign previews.

**v2_schedule pinned-day header — FINAL solution + big time-sink lesson (2026-07-17):** Getting the day header to freeze at the top on mobile cost many rounds. Two separate traps stacked on top of each other:
- ★★ **Native CSS `position:sticky` DOES NOT reliably work in DJ's phone webview** — it pins when scrolling UP but not DOWN, because the address-bar dynamic viewport changes the scroll container height mid-scroll. Do NOT trust `position:sticky;top:0` for a must-stick header on mobile. **The solution that works = an INTERNAL-SCROLL FRAME:** make `body` a non-scrolling flex column (`height:100vh;height:100dvh;display:flex;flex-direction:column;overflow:hidden`), pin the ribbon + blue header with `flex:0 0 auto`, and put the day list in an inner scroller `.body{flex:1 1 auto;min-height:0;overflow-y:auto;-webkit-overflow-scrolling:touch}`. Inside THAT internal scroller, `position:sticky;top:0` on `.day-head` works perfectly both directions (the scroll container is now a real fixed-height element, not the address-bar-affected window).
- **The 1/8" gap DJ saw** between the blue header and a pinned day header (list visibly scrolling through the gap = looked unprofessional): fixed by removing the scroller's TOP padding (`.body` padding `14px 14px 90px`→`0 14px 90px`) and the header's TOP margin (`.day-head` margin `11px 0 8px`→`0 0 9px`), then restoring initial breathing room with `.filter-wrap{margin-top:12px}` + `.day-sec{margin-top:12px}`. Net: pinned day header butts flush against the blue header, nothing peeks between. Deployed commit 06476f66.
- ALSO remember the [[project_sw_cache_stale_page]] trap that made ALL of the above "not appear to work" for rounds: the service worker (auth.py, cache `wsc-shell-v4`) serves `/static/*` stale-while-revalidate → DJ sees the PREVIOUS deploy.
