**Postpone tool (built 2026-08-18, DJ request).** Common case: DJ confirms jobs 3-4 days out, customer says they're on vacation / need to reschedule but not at that moment. Tool = park the job OFF the schedule but KEEP it, so it can be rescheduled later. DJ chose placement = **the Inbox** (the ⚡ Actions menu in v2_inbox), because the inbox is where he learns about the postpone (customer's reply). He explicitly did NOT want it on the customer confirm link ("invites people to postpone... makes it easy").

**The gate facts this relies on (verified in code 2026-08-18):**
- **Daily schedule / day-plan** (`scheduler.py` build_day_plan, `dashboard.py` calendar_jobs) gates on `date_order` = that day + `state in ['sale','done']` + `x_studio_x_studio_workiz_status != 'Canceled'`. **It does NOT exclude 'Submitted'.** So flipping status to Submitted alone does NOT pull a confirmed job off its day — **the date_order is what removes it from the day.** (CLAUDE.md's "Submitted jobs aren't on the schedule" is about Phase-3 DRAFT quotations, state=draft — not an already-confirmed job.)
- **"Needs scheduling" tab** (Command Center v2_command.html) = 3 feeds: **Skipped** (`/api/calendar_jobs` past-dated confirmed jobs, -90d→today), **Overdue backlog** + **future to-place** (`/api/scheduled_sos`, dashboard.py ~8808). scheduled_sos queries **`x_studio_x_studio_workiz_status == 'Submitted'`** (overdue = Submitted + date_order in [today-365, today) + real job_type; to-place = Submitted + date_order >= today). Company_id=1.

**★ FINAL mechanism = a dedicated `'Postponed'` status (DJ 2026-08-18, v2). The first version moved date_order to last-Saturday + set 'Submitted' — DJ found the fake past date unintuitive ("the Saturday thing"). Replaced by a real status.** `x_studio_x_studio_workiz_status` is a **char** field (id 13806, ttype char, NOT a selection) so 'Postponed' is a valid value with NO Odoo schema change. `scheduler.postpone_odoo_so(so_id, reason, by)` now: (1) writes `x_studio_x_studio_workiz_status='Postponed'` and **keeps date_order intact** (so Needs-scheduling shows the real "was <date>"); (2) clears confirm flags `wsc.reminders.confirmed.<id>`='' + `wsc.sched.<id>`='{}' + deletes HUD `sched_req:<id>` + chatter note. State stays 'sale' (no draft-revert). ONE status flip both removes it from the schedule AND surfaces it in Needs scheduling, because:
- **Schedule/route queries EXCLUDE 'Postponed'** — 5 sites, all changed to add 'Postponed' to their Canceled/Done not-in list: `scheduler.build_day_plan` (~210), `scheduler` slot-fit `_can_fit` (~443), `dashboard.api_calendar_jobs` (~9125, the calendar + on-schedule + skipped feed), `dashboard` candidates route-planner (~3584), `field.py` candidates route-planner (~2353).
- **Needs-scheduling feed INCLUDES 'Postponed'** — `dashboard.api_scheduled_sos` base_dom (~8815) changed `status = 'Submitted'` → `status in ['Submitted','Postponed']`.
- **Reschedule promotes it** — `scheduler.api_schedule_reschedule` promote check (~912) now `cur_status.lower() in ('','submitted','postponed')` → schedule_odoo_so re-sets date + status 'Scheduled'.
Verified end-to-end against live Odoo (throwaway test SO 17575, product 141): status Scheduled → on-schedule=True/needs-sched=False; after Postponed (same date) → on-schedule=False/needs-sched=True; date preserved; reschedule-promote=True. Commits scheduler 26e9b9c, dashboard 57a6271, field 58394db.

**Also in the FIELD job-detail ⋯ menu (DJ 2026-08-18):** v2_field.html job menu got two items next to 🔁 Reschedule — **🗓️ Postpone — needs scheduling** (`postponeJobFromMenu` → confirm → `POST /api/postpone_job {so_id}`, a direct-by-so_id twin of the inbox endpoint, in scheduler.py, calls postpone_odoo_so + cache-bust) and **📄 Duplicate job** (was missing from the field menu though it existed in v2_customers). Duplicate REUSES the existing reschedule day-planner modal in a "duplicate mode" (`_jobRsDupMode` flag flips the title/button + makes `submitJobRs` POST `/api/duplicate_job {schedule:true}` instead of reschedule) — no new sheet. `dashboard.api_duplicate_job` now **defaults job_type from the source SO** when the caller omits it, so the field duplicate (no type picker) carries the original job's type. Postpone item is hidden when status is Done.

**Inbox wiring (sms.py):** `_find_upcoming_jobs(partner_id)` = ALL upcoming confirmed jobs on the customer's property tree (soonest first, with address+amount) — needed because a customer often has several the same week (Wayne Geringer had 2 Thursday jobs: SO 004337 + 004338). `POST /api/inbox/postpone` = two modes on one endpoint: no `so_ids` → returns the upcoming jobs for the picker; `so_ids[]` → parks each via postpone_odoo_so + busts the sched cache. No text is sent (postpone is internal; DJ replies to the customer separately). Frontend: `openPostpone()` in v2_inbox → fetch jobs → bottom-sheet picker (all pre-checked) → park.
