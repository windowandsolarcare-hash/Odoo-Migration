Inbox Assistant **Phase 1** (built 2026-08-02, my lane). On a real customer inbound (AFTER the existing STOP/robocall/lead-call guards), triage the thread → post ONE HUD card `inbox_ai:<norm>`. **P1 acts only on Respond**; schedule/reschedule/cancel just NOTE the intent on an attention card (P2+ does the actions). Spec = `3_Documentation/INBOX_ASSISTANT_SPEC.md`; lead's drafted reply-brain = `3_Documentation/INBOX_ASSISTANT_PROMPT.md` (NOT yet adopted — decided to keep my lean Haiku classifier for P1, fold lead's full 4-intent SYSTEM_PROMPT in at P2). All in **routers/owner/sms.py**.

**Flow (sms.py inbound ~L764):** after `conv['draft']=_draft_reply(...)` → `_inbox_ai_card(from_norm, name, partner_id, body, context, thread, conv['draft'], conv)`.
- `_triage_thread(thread, message, context)` (Haiku) → `{intent: respond|schedule|reschedule|cancel, needs_response: bool, data_needed: [pricing|availability|payment|history], reason}`.
- **respond + needs_response** → `kind='approval'` card, title "Reply to <First>", draft body = `_draft_reply` re-run with FACTS appended, `on_approve` POST `/owner/api/inbox_ai/approve {c,intent}` (sends via messaging.send). Edit box + reject supported (`/owner/api/inbox_ai/reject` → 3 alternates via `_draft_options`).
- **not needs_response** ("thanks") → `kind='attention'`, "<First> — no response needed", Done clears. NO draft (DJ §11.1).
- **schedule/reschedule/cancel** → `kind='attention'`, "<First> — wants to book/reschedule/cancel", open-thread action only (P2+ acts).

**NEVER invent a price/date/address (the #1 safety rail).** `_draft_reply`'s system prompt forbids stating any price, PRICE RANGE, estimate, date, or address not present in the conversation/data. Enrichment = `_inbox_ai_facts(data_needed, partner_id)`, which uses the LEAD'S CLEAN HOOKS (not dashboard internals): pricing ← `from .new_job import quote_prices` (`{'rates','labels','difficulty'}`); availability ← `from .new_job import open_days_for_partner(partner_id, 3)` (`{'ok','city','options':[{date,time}]}`) → offers 3 REAL open days ("offer only these"), falls back to "let me check + get right back to you" if no property/coords; payment = static Zelle/cash/check/card. `_pretty_day('YYYY-MM-DD')`→"Thursday, September 3" (no ordinal). VERIFIED live: a solar-price question drafts "how many panels, or I can send a quote" — no invented number (a first cut had invented "$150–$300", fixed).

**thread_tail (spec §12, DJ 2026-08-02):** every inbox_ai card carries `thread_tail` = `_thread_tail(conv, 3)` = last ~3 msgs `[{who:"You"|"Them", dir:"in"|"out", body(≤280), ts}]` oldest-first, so DJ judges the reply on the card without opening the thread. On BOTH approval + attention cards. **feed.validate_item does NOT strip unknown keys** — so arbitrary card fields like `thread_tail` persist through submit_item. HUD must render `item.thread_tail` (mailed lead to wire the render — my card, my layout).

**Full prompt on BOTH tiers (DJ 2026-08-02, corrected his earlier "keep lean for P1").** Escalation = MODEL POWER only, NOT prompt richness (a lean Haiku with a thin prompt = confident-wrong). `_INBOX_BRAIN` (module const in sms.py, = the full `3_Documentation/INBOX_ASSISTANT_PROMPT.md` body, `{today}` filled by `_inbox_brain()`) is now the system prompt for BOTH `_triage_thread` (classify pass — full brain + the strict-JSON contract appended) AND `_draft_reply` (draft pass). `_draft_reply` gained `escalate` param → `model = CLAUDE_MODEL if escalate else CLAUDE_HAIKU` (same prompt both). `_thread_is_hard(thread,message)` decides escalation (≥8 thread lines, latest text >240 chars, or ≥2 '?'). In P1 the model has NO tools, so the prompt's "call quote_prices()" lines are satisfied by facts injected via `_inbox_ai_facts` — the draft user-message says "You have NO tools here — use only the data below." `CLAUDE_MODEL` now imported in sms.py. Verified: solar-price Q still defers ("priced per panel — what's your panel count, or I can swing by and give you a quote?"), no invented number, Dan's voice.

**PHASE 3 — RESCHEDULE + CANCEL (act on intent) + BACKFILL (built + tested 2026-08-03, sms.py).** DJ picked reschedule next (live pain: Dick Palomba "can we push to 11/18? same time" fell in the gap). `_inbox_ai_card` now ACTS on reschedule/cancel instead of just noting them:
- **Helpers:** `_find_upcoming_job(partner_id)` = soonest `sale.order` where `partner_id child_of pid`, state='sale', date_order>=today PT, workiz_status not in [Done,Canceled], returns `{so_id,name,dt_pt,job_type}` (dt_pt = date_order UTC→_PT). `_fmt_pt_dt(dt_pt)`→"Wednesday, November 18 at 8:00 AM". `_parse_reschedule(thread,message,current_pt)` = Haiku JSON `{date,time,same_time,ambiguous}` ('same time'/no time → keep current time; relative dates vs today).
- **reschedule branch:** finds the job → parses new date/time (time-only change keeps the day; same_time keeps current time) → **approval** card, title "Reschedule <First> → <Mon D>", why_now "<current> → <new>", draft confirm "Moved you to <new>. See you then! – Dan", on_approve `POST /api/inbox_ai/reschedule {c,so_id,date,time}`. No job/date → falls through to attention.
- **cancel branch:** finds job → **approval** card "Cancel <First>'s job", courteous draft, on_approve `POST /api/inbox_ai/cancel {c,so_id}`. Never auto-deletes.
- **Endpoints:** `/api/inbox_ai/reschedule` → `scheduler.schedule_odoo_so(so_id, dt_pt, set_status=True)` (dt_pt = `strptime(f'{date} {time}','%Y-%m-%d %H:%M').replace(tzinfo=_PT)`) THEN `messaging.send` confirm (idem `inbox_ai_resched:<so>:<date>`, honors quiet-hold). `/api/inbox_ai/cancel` → tries `from routers.owner.new_job import cancel_job` else FALLBACK `action_cancel` + write status Canceled, then send. Both delete_item the card. **cancel_job NOT yet exposed by lead — the fallback is what runs (tested working).**
- **Backfill:** `POST /api/inbox_ai/backfill {token,limit}` (CRON_SECRET) iterates `INDEX_KEY` threads whose LAST msg is inbound, not automated, no existing `inbox_ai:` card → runs `_inbox_ai_card(..., only_actionable=True)` (the new flag skips posting a no-response card for settled threads). Idempotent. **DJ/lead triggers it ONCE** — I did NOT run it against prod (would card real open threads prematurely); verified auth guard + the card mechanics via the reschedule/cancel tests.
