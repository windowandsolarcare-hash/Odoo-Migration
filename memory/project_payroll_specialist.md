**2026-07-26 — first specialist built ([[project_operating_system_vision]], seam [[project_attention_feed_contract]]).** `routers/owner/specialist_payroll.py` (registered in main.py, prefix /owner).

**What it does (Part A):** `prepare_payroll(start,end)` reads `hr.attendance` for the period and computes per-employee regular / OT / double-OT + dollars using the SAME pipeline as `dashboard.api_payroll_gusto_export` (imports `_att_fields, _att_date_range_utc, _format_att_for_ui, _round_quarter` from dashboard; replicates the nested `_ca_daily_split` = CA daily OT 0-8 reg / 8-12 OT / 12+ double). Dollars = reg×wage + OT×1.5 + DOT×2, wage from `hr.employee.hourly_wage`. Open shifts (no clock-out) are excluded from pay (as the CSV excludes them) and FLAGGED — those hours silently drop otherwise. Submits ONE `approval` feed item `id=payroll:<start>_<end>` via `feed.submit_item`. Idempotent; withdraws (`delete_item`) if the period is already `payroll.approved.*`/`payroll.submitted.*`, or has no hours.
- **Endpoints (my lane):** `POST /owner/api/payroll/prepare {start,end}` (defaults to last Mon–Sun) triggers it. `POST /owner/api/payroll/specialist_approve {start,end}` = the item's `on_approve` (inbox UI calls it on approve, then acks) — sets `payroll.approved.{start}.{end}`, withdraws the card, returns the Gusto CSV link (`/owner/api/payroll/gusto_export`).
- **Verified live:** period 2026-07-20..26 → "Daniel J Saunders 17.25 reg + 2.25 OT = $618.75", **exactly matching the Gusto CSV** (wage $30/hr). Item well-formed, ranked above the lead's demo cards. App still booted after the main.py edit.
